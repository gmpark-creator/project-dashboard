## 1. 현재 화면이 "단순한 타일 게임"처럼 보이는 원인 (자기 진단)

1. **축척이 틀렸다.** 부산 전체(약 35×38km)를 150×90 타일에 넣어 1타일 ≈ 250m. 집 한 채, 사무실 빌딩, 크레인이 모두 "한 블록 크기"라 동네가 존재하지 않는다. 박사가 말한 "실제 거리를 걷는 느낌"이 원천적으로 불가능한 구조.
2. **시점이 섞였다.** 지면은 완전 수직 탑다운, 건물은 작은 정면 스프라이트. 지붕·벽면·접지의 관계가 없어 높이감이 안 생긴다.
3. **해상도 한계.** 16px 타일 / 16×21 캐릭터를 3배 확대 → 얼굴은 읽히지만 팔다리·옷 주름·보행 무게중심을 표현할 픽셀이 없다(몸통 5줄, 다리 4줄).
4. **지면이 타일 단위 노이즈.** 전이(autotile) 없이 사각 계단형 해안선, 2칸짜리 흙길이 차도·보도 구분 없이 깔림. 반복 무늬가 그대로 보인다.
5. **배치가 무작위 산포.** 주택·나무를 해시로 흩뿌렸다. 골목·블록·마당·축대 같은 "도시의 문법"이 없다.
6. **렌더링 규율이 깨짐.** 캔버스 알파 타원 그림자, 안티에일리어싱 곡선(케이블), 반투명 구름 그림자가 도트와 따로 논다.
7. **지리 오류(실측과 대조해 확인).**
   - 부산항대교는 **사장교**인데 현수교로 그림.
   - 광안대교는 **자동차 전용**(보행·자전거 불가)인데 걸을 수 있는 L자 다리로 임의 배치.
   - 영도와 본토를 잇는 다리는 4개(영도대교·부산대교·남항대교·부산항대교)인데 1개 + 임의 1개.
   - 출입국청은 충장대로 해안 쪽(중앙동, 북항 서안)인데 내륙 서쪽에 둠.
   - 남항(자갈치~영도 사이 수역)이 이름도 형태도 없음. 을숙도대교 위치도 임의.

→ 결론: 색이나 장식을 더하는 걸로는 안 풀린다. **축척·시점·해상도·배치 방식** 네 가지를 동시에 바꾼다.

## 2. 시점·해상도·비례·팔레트

### 2-1. 시점: 일관된 3/4 탑다운(사선 위쪽 시점)
- 지면은 위에서, 모든 수직면(건물 입면·담장·축대·안벽·나무 줄기)은 **정면을 일정 높이로 세워** 그린다. 한 화면의 모든 오브젝트가 같은 각도.
- 건물 = **바닥 발자국(footprint) + 정면 입면 + 지붕** 3층 구조. 발자국이 충돌 영역, 입면이 앞을 가리는 영역, 지붕이 뒤를 가리는 영역.
- 앞뒤 관계: 건물·나무를 **발자국 하단선 기준 y정렬**. 캐릭터가 건물 북쪽(뒤)에 서면 입면·지붕에 가려지고, 남쪽(앞)에 서면 건물을 가린다. 나무는 줄기만 충돌, 수관은 위로 겹침.

### 2-2. 원본 해상도 · 화면 배율
| 항목 | v1 | **v2 제안** | 이유 |
|---|---|---|---|
| 타일 | 16px | **32px** | 보도 경계석·차선·안벽 볼라드·창틀 깊이를 표현할 픽셀 확보 |
| 캐릭터 | 16×21 | **24×40** (머리 14 / 몸통 12 / 다리 14) | 머리:몸 ≈ 1:1.9. 귀여움은 유지하되 팔·다리·수트 자락·넥타이가 분리되어 읽힘 |
| 화면 배율 | 3× (1440×900) | **2×** (1440×900), 1× 미만 금지 | 캐릭터 화면 크기 63px → **80px**로 소폭 증가, 시야는 30×17타일(=480m) → 22×14타일(=330m, 1타일≈15m) |
| 축척 | 1타일 ≈ 250m | **동네 맵 1타일 ≈ 12~15m** | 차도 2~4칸, 보도 1칸, 건물 2~8칸 폭 → "거리"가 생김 |

- "다 같이 키워 시야만 좁아지는" 변경이 아님: 타일·캐릭터의 **원본 픽셀 수를 2배**로 올리고 **배율은 3→2로 낮춘다**. 화면상 캐릭터는 1.3배, 디테일은 약 2.3배.
- 모바일(390×844): 배율 1.5(정수 아님 → 픽셀 깨짐 방지 위해 **1× 렌더 후 CSS 2× 확대 + 캔버스 폭 조정**으로 정수 배율 유지).

### 2-3. 팔레트 · 픽셀 규율
- **고정 팔레트 48색**(색상 램프 12개 × 4단계, 그림자 쪽으로 색상 이동(hue shift) — 그림자를 검정 섞기가 아니라 청보라 쪽으로). 모든 스프라이트·타일·UI 픽셀이 이 팔레트에서만 나옴. 빌드 시 팔레트 외 색 검출 게이트(§5 G8).
- 광원 = 왼쪽 위 고정. 그림자는 **오른쪽 아래로 떨어지는 픽셀 블록 + 2단계 디더**. 캔버스 `ellipse`/알파 그라데이션/안티에일리어싱 곡선 **금지**(케이블도 픽셀 브레젠험으로).
- 텍스트는 계속 DOM(Galmuri, OFL) — 캔버스에 한글 도트를 직접 찍지 않음.

### 2-4. 캐릭터 (에이전트 고르고 v2)
- 현재 디자인 정체성 유지: 네이비 수트, 빨간 넥타이, 머리 위 선글라스, 반짝이는 큰 눈, 볼터치.
- 4방향 × **6프레임 걷기**(접지→중간→차기), 머리 1px 상하 보행 바운스 + 팔 반대 스윙, 측면은 뒷다리 한 톤 어둡게(무게중심), 대기 2프레임(호흡) + 깜빡임.
- 왼쪽 = 오른쪽 반전 금지 검토: 가르마·넥타이 방향 때문에 **좌우 개별 도트**(반전 시 가르마 반대로 가는 문제 해결).

### 3-2. 지키는 지리 관계 (거리는 압축해도 방향·인접·수역 연결은 유지)
1. 낙동강 하구: 강서(명지·신항)가 **서안**, 사하(하단·다대포)가 **동안**, 을숙도가 하구 한가운데. 을숙도대교가 섬을 관통해 사하↔명지.
2. 영도: 본토 **남쪽의 섬**. 북쪽 좁은 수로(영도대교·부산대교 → 중앙동·남포), 서쪽 남항(남항대교 → 서구 암남), 동쪽 북항 입구(부산항대교 → 남구 감만). 섬 중앙 봉래산, 남동단 태종대.
3. 원도심 남북 축: 부산역(북) → 중앙동·출입국청(남, 해안) → 남포·자갈치(남서, 남항) → 영도. 동쪽 바다가 북항, 남쪽 바다가 남항.
4. 동부: 수영강이 북→남으로 흘러 수영만에 닿고, **서안 = 수영구(망미·민락), 동안 = 센텀시티(우동)**. 광안리는 수영만 서쪽 해변, 광안대교는 남천동에서 수영만 입구를 가로질러 우동(마린시티)으로. 동백섬을 지나 해운대해수욕장, 배후에 장산.
5. 산이 도시를 가른다: 금정산(북) – 백양산 – 구덕산·엄광산 줄기가 낙동강 쪽과 원도심을 가르고, 산허리에 산복도로·감천문화마을. 황령산이 서면과 광안리·남구 사이를 막음. 영도는 봉래산 하나가 섬 대부분.

### 3-3. 월드 구조 제안 — **지역 분할 (부산 전도 + 동네 맵)**
한 장에 부산 전체를 넣으면 캐릭터·건물이 작아지는 문제가 v1의 근본 원인이므로, 장르 문법 그대로 **지역 맵 분할**로 간다.

- **① 부산 전도 (overview)**: OSM 해안선·하천을 등거리 투영 후 단순화·래스터화. 1타일 ≈ 250m. 걷는 맵이 아니라 **이동·위치 확인용**(미니맵, 지역 선택). 텍스트를 가려도 낙동강 하구·영도·북항/남항·수영만·해운대 해안선으로 부산이 보이는지가 이 레이어의 게이트.
- **② 동네 맵 (walkable)**: 1타일 ≈ 12~15m, 맵당 약 160×120타일(≈2.2×1.7km). OSM 가로망·해안선·부두를 **형태 참고**로 깔고, 블록 안 건물은 우리 스프라이트로 배치(실제 건물 1:1 복제 아님).
  - **중앙동 구역**: 부산역 ~ 중앙동(출입국청) ~ 남포·자갈치 ~ 영도 북단. 영도대교·부산대교(보도 있음, 보행 가능), 북항 안벽·크레인, 용두산 부산타워, 산복도로 계단 골목.
  - **센텀 구역**: 수영강 양안 ~ 센텀시티역·벡스코 ~ 사무실 ~ 마린시티 ~ 광안리 일부. 광안대교는 **배경(보행 불가)**으로 사실대로.
- **③ 구역 간 이동**: 맵 가장자리 출구 + **지하철역 입구**(중앙역·부산역 / 센텀시티역). 들어가면 전도가 열리고 목적지 선택 → 해당 맵 역 출구로 스폰. (실제 노선 1호선 ↔ 서면 환승 ↔ 2호선을 표기만 하고, 탑승은 즉시 이동.)

### 3-4. 렌더 레이어 · 충돌 일치
- 레이어: 지면 → 지면 장식(차선·맨홀·보도블록) → **y정렬 레이어**(건물 입면·담장·나무·사람·캐릭터) → 오버헤드(지붕 처마·나무 수관·교량 상판 위 케이블) → 날씨·DOM 라벨.
- 충돌은 **맵 데이터의 발자국 레이어에서만** 생성하고, 같은 데이터로 입면을 그린다 → "보이는 벽 = 막히는 벽". `?debug=collision` 오버레이로 시각 검증.
- 문: 건물마다 `door` 타일 지정 → 그 앞 1칸은 반드시 보행 가능(게이트 G4).

## 4. 대표 구역으로 그래픽 방향 먼저 검증

- **대표 구역 = 중앙동 구역 (출입국청 포함).** 이유: 한 화면 안에 해안 안벽, 교량(영도대교 도개 상판), 고층(부산타워), 산복도로 주택·계단, 차도·보도·광장, 정부청사 입구가 모두 들어와 **그래픽 문법 전체를 한 번에 시험**할 수 있다. 센텀 구역은 유리 고층 위주라 문법 검증 범위가 좁음.
- 대표 구역은 `/agent-gorgo/v2/`에서만 공개. 메인 URL은 v1 그대로.
- 박사 피드백 → (필요 시 R2) → 센텀 구역 + 전도 + 지하철 이동 → 메인 URL 교체.
- ⚠️ 그래서 "사무실 스폰 → 출입국청" 완료 기준은 **대표 구역 단계에서는 측정 불가**(사무실이 센텀 구역에 있음). 대표 구역 단계에서는 "역 출구 스폰 → 출입국청 문" 경로로 대체 측정, 최종 단계에서 원 기준으로 측정. (판정 요청 #D3)

## 5. 구현 범위와 검증 기준

### 5-1. 1단계 범위 (GO 후)
1. 엔진: 32px 타일, 레이어 렌더러, 동네 맵 로더(맵 = JSON 데이터), 발자국 기반 충돌·y정렬, 문/출구 정의, 기존 입력·패널 모듈 이식(BLOCK 수정분 포함), `?debug=collision`, `?nolabels`.
2. 아트: 48색 팔레트, 지면 autotile(바다·안벽·모래·잔디·보도·차도·광장 경계), 건물 키트(정부청사·상가·주택·산복도로 주택·아파트·고층·부산타워), 교량(영도대교 상판·난간·트러스), 크레인, 나무, 소품(가로등·벤치·볼라드·신호등).
3. 캐릭터 v2: 24×40, 4방향(좌우 개별) × 6프레임 걷기 + 대기.
4. 맵: **중앙동 구역 1장**. OSM 가로망 형태 참고로 저작.
5. 업무 기능 **없음**. 출입국청 패널은 기존 자리표시 유지.

범위 밖: 센텀 구역, 전도, 지하철 이동, 업무 모듈, 메인 URL 교체.

### 5-2. 게이트 (구현 완료 보고 시 원자료로 제출)
- **G1 전후 비교**: 같은 뷰포트(1440×900, 390×844)에서 v1 URL vs v2 URL 실제 플레이 화면. 콘셉트 이미지 대체 금지.
- **G2 라벨 가림**: `?nolabels` 화면에서 해안선·교량·항만·산복도로로 원도심/영도임이 보이는지(박사 시각 판정 — CLI로 대체 불가).
- **G3 충돌 = 시각**: `?debug=collision` 오버레이 캡처 + 자동 검사(모든 건물 입면 하단에 충돌 발자국이 있고, 보이는 길 타일에는 충돌이 없음).
- **G4 도달성**: 실제 `blocked()`로 픽셀 BFS — 스폰 → 출입국청 문, 모든 `door` 앞칸 보행 가능, 교량 양끝 연결.
- **G5 입력 회귀**: `tools/qa.html` A–F 시나리오 v2 엔진에서 전부 통과 + 터치 조이스틱 이벤트 시나리오.
- **G6 지리 관계 자동 단언**: 맵 데이터에서 부산역 y < 중앙동 y < 영도 y, 출입국청 동쪽이 바다(북항), 영도대교·부산대교가 같은 수로를 건넘 등 §3-2 관계를 코드로 assert.
- **G7 이동 장면**: 스크립트 입력으로 실제 페이지를 걷게 하고 연속 프레임 캡처(앞뒤 가림 장면 포함: 건물 뒤로 지나가기, 나무 수관 아래 지나가기).
- **G8 픽셀 규율**: 렌더 결과 PNG의 고유 색이 팔레트 48색(+DOM 영역 제외) 안에 있는지 검사, 소스에서 `ellipse(`·`createLinearGradient`·`imageSmoothingEnabled = true` 사용 0건.
- **G9 성능**: 1440×900에서 프레임 시간 측정(목표 16.7ms 이하) 보고.

### 5-3. 예상 위험과 완화
| 위험 | 완화 |
|---|---|
| 코드로 찍는 도트의 미적 한계(사람 손 도트 대비) | 키트 단위로 만들고 대표 구역에서 박사 판정을 먼저 받음. 부족하면 R2에서 외부 CC0 에셋 혼용 여부를 박사에게 질문 |
| OSM 데이터 라이선스(ODbL) | 형태 참고 + 화면에 "지도 데이터 © OpenStreetMap contributors" 표기. 원시 데이터 파일은 레포에 넣지 않고 변환된 타일 맵만 보관 |
| 실제 건물 1:1 재현 유혹 → 작업량 폭증 | 가로망·해안선·랜드마크만 실측 형태, 블록 내부 건물은 키트 조합 |
| 맵 데이터 커짐(160×120 × 다층) | 레이어별 RLE 또는 Uint8 base64 — 페이지 1MB 이하 목표 |
| 교량 보행 사실성 | 영도대교·부산대교는 보도 실재 → 보행 가능. 광안대교·부산항대교는 자동차 전용 → 배경 |

## 6. Codex에게 판정 요청 (번호별)
- **D1** 지역 분할(전도 + 동네 맵 + 지하철 이동) vs 단일 연속 맵.
- **D2** 해상도: 타일 32 / 캐릭터 24×40 / 데스크톱 2× · 모바일 정수 배율 유지 방식.
- **D3** 대표 구역 = 중앙동, 그리고 대표 구역 단계의 완료 기준을 "역 출구 스폰 → 출입국청 문"으로 대체 측정하는 것.
- **D4** OSM 벡터 데이터 형태 참고 + ODbL 표기 방식.
- **D5** 광안대교·부산항대교 보행 불가(사실대로 배경 처리).
- **D6** 게이트 G1–G9가 "trivially-true"가 아닌지 — 특히 G2(박사 시각 판정)와 G8(팔레트 검사).
- **D7** v2 별도 URL에서 진행하고 메인 URL은 최종 단계까지 v1 유지.
