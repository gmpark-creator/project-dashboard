## 2. 제안 설계 (Claude Thesis) — 4-tier 학습 분류

기존 175문항을 학습 우선순위로 4계층 분할:

1. **중요개념 (기존, 불변)** — 꼭 공부. 고빈출·반복 클러스터. *손대지 않음.*
2. **중빈도 유형 (신규)** — 가능하면 공부. 남은 문항 중 **토픽이 2회 이상 반복**되거나 기초·학습가치가 높은 문항을 토픽 클러스터로 묶음. 남은 문항의 본체.
3. **희소유형 (재컷·축소)** — 여유되면 한 번. 진짜 1회성이지만 그래도 일별 가치가 있는 낯선 절차/예외. 8개 고정 해제, 과목별 가변.
4. **버림 (폐기)** — 포기. 1회성·초저빈도·과도한 계산·재출제 가능성 희박. 어느 학습 카테고리에도 노출 안 함(단 정답해설 전수 뷰에는 그대로 존재).

분류 규칙(객관 기준 + 주관 판단):
- 남은 문항을 토픽으로 클러스터링 → **클러스터 멤버 ≥2 ⇒ 중빈도**.
- 멤버 1개(1회성) ⇒ 낯섦·일별가치 있으면 **희소유형**, 그렇지 않으면 **버림**.
- 현 희소유형 항목 중 **이미 중요개념에 커버된 것은 희소에서 제외**(이미 학습됨) → 자연 컬링.
- 모든 남은 문항은 중빈도·희소·버림 중 정확히 하나에 배정(누락/중복 0). 검증 스크립트로 강제.

데이터 계약 (기존 rare-types 계약 재사용 → 렌더러 최소수정):
- 신규 `bosesa-midfreq.js`: `BOSESA_MID_FREQ = { generated, years, title, method, subjects:{ 1..5:{ subjectNo, subjectName, items:[ { title, tier, representativeYear, representativeNo, members:[{year,no}], reason, studyFocus, watch:[≥3], examTip } ] } } }`. 문제 원문·정답·근거는 `bosesa-data-*`에서 런타임 참조(중복 저장 안 함).
- `bosesa-rare-types.js`: items에서 폐기분 제거(축소). 구조 동일.

구현(렌더러 재사용):
- 데스크톱 `index.html`: `renderBosesaRareTypes`를 복제해 `renderBosesaMidFreq` 신설(대표문항+멤버목록 표시). 사이드바 5개 과목 메뉴에 「중빈도 유형」 버튼 추가, 활성로직 추가, 색=sky(amber=개념/emerald=해설/rose=희소/**sky=중빈도**), 아이콘 fa-chart-column.
- 모바일 `bosesa-mobile/index.html`: 동일 패턴(chip + injectOnce + renderMidFreq + URL param).
- 대시보드 `projects-data.js`/노트: 4번째 카테고리 반영.
