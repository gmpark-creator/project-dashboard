# 08 · Claude R2 — UX 보정 (Codex R1 피드백 반영)

변증법 흐름: **Claude R1**(UX/제품 설계·프로토타입) → **Codex R1**(아키텍처 반박·계약·라우팅 config·열린질문 답변) → **이 문서 = Claude R2**.

Codex가 지적한 핵심: *제품이 영상 provider의 기능(4K·특정 모델·구간 재생성·네이티브 오디오·자동 품질점수)을 "항상 보장"되는 것처럼 표현*하는 부분을 줄여야 한다. 단, **사용자 경험은 여전히 쉽고 명확하게**, **모델명은 화면에 비노출**.

> 원칙 재확인: 사용자는 *의도(intent) + 티어 + 결과*만 본다. 엔진·capability·내부 실행 모드는 라우터/폴백 뒤에 숨긴다. 이 문서의 "수정 후" 문구는 **사용자에게 보이는 카피**이고, "내부 전제"는 Codex 계약(`codex/config/*`, `codex/api/openapi.json`)이 책임진다.

## 1. Veo 3.1 4K 표현 수정
**문제:** "Veo만 네이티브 4K", "4K ✨고품질필요"처럼 4K를 특정 엔진이 항상 보장하는 기능으로 표기.
**원칙:** 사용자에겐 "고해상도 옵션"으로, 내부적으로는 *provider 지원 시 직접 / 아니면 렌더 업스케일*. 기본 계약은 720p/1080p.

| 위치 | 수정 전 | 수정 후(사용자 노출) |
|---|---|---|
| 프로토타입 내보내기 해상도 | `[720p] [1080p] [4K ✨]` | `[720p] [1080p] [4K]` + 하단 helper: "4K는 고해상도 마무리 옵션이에요 — 지원되면 그대로, 아니면 업스케일로 처리해요." |
| 02-screens 화면6 해상도 | `[720p] [●1080p] [4K ✨고품질필요]` | `[720p] [●1080p] [4K · 고해상도(업스케일 가능)]` |
| (참고) 07 부록/엔진맵 | "유일 네이티브 4K" | Codex가 이미 보정: 4K=export/upscale 옵션, 기본 720/1080 ([codex/config/provider-capabilities.json]) |

**내부 전제(Codex):** `ExportSpec.resolution=4k`는 provider capability 확인 또는 `render_upscale`로 충족. 제품 기본 계약은 720p/1080p.

## 2. Runway Gen-4 Turbo 표현 수정
**문제:** "빠른 드래프트(무음) → Gen-4 Turbo"처럼 Turbo를 text-only 빠른 기본 엔진으로 표기. 공식 모델표상 Turbo는 image-to-video 입력 후보.
**원칙:** 사용자는 엔진명을 모른다 → **"빠른 미리보기"** 티어로만 표현. 엔진 선택은 라우터가 *입력 타입 필터 후* 결정.

| 위치 | 수정 전 | 수정 후 |
|---|---|---|
| 사용자 UI(전 화면) | (엔진명 없음, 유지) | 변경 없음 — "빠른 미리보기" 유지 ✓ |
| 04-templates "엔진 적합(백엔드)" | "빠른 동적 페이싱 → Gen-4 Turbo / Ray 2 Flash" | 공통 원칙에 주석 추가: 이 엔진명은 *예시 후보*이며 라우터가 입력타입·길이·비율·지역 필터 후 선택. **Gen-4 Turbo는 image-to-video 후보(text-only 빠른 기본값 아님)** |
| 03-ux-rules §10 라우팅 | `tier=fast → 빠른 미리보기` | 유지 + 주석: fast 티어의 엔진은 라우터 결정. text-only 컷에 image-input 모델 미배정(Codex `routing.config.json` 필터) |

**내부 전제(Codex):** `RoutingEngine`은 `requirements.imageToVideo` 등 입력 타입 필터를 먼저 적용. text-only fast 요청에 Turbo를 기본 배정하지 않는다.

## 3. 부분 재생성("이 부분만 다시") 표현 수정
**문제:** "서브클립(2~16초) 부분 재생성 **지원**"이 모든 엔진에서 보장되는 것처럼 표기.
**원칙:** UX 라벨 유지. 단 사용자에겐 *결과 보장(좁은 구간)*이 아니라 *의도(가능한 가장 좁게) + 안전장치(이전 후보 보존)*로 설명.

| 위치 | 수정 전 | 수정 후(사용자 노출) |
|---|---|---|
| 비교화면 버튼 | `✂ 이 부분만 다시` | `✂ 이 부분만 다시` (유지) + 툴팁: **"이전 후보는 그대로 보존돼요. 가능한 가장 좁은 범위로 다시 시도하고, 안 되면 컷 전체를 새로 만들어요."** |
| 03-ux-rules UX-5.2 | "서브클립(2~16초) 부분 재생성 **지원**" | "**이 부분만 다시** — 가능한 가장 좁은 범위로 재시도(엔진이 구간 재생성을 지원하면 그 구간만, 아니면 컷 전체 재생성). **이전 Take는 항상 보존.**" |
| 02-screens 화면4 "다시/부분 다시" | "전체 재생성 vs 서브클립(2~16s)만" | "전체 재생성 vs **가능한 최소 범위 재시도**(capability-gated). `regenerate(scope: shot\|segment)` — segment는 미지원 시 shot으로 폴백" |

**내부 전제(Codex):** `scope="segment"` 수신 → provider가 segment retake/video-to-video 지원 시 해당 구간, 미지원 시 shot 재생성 + 기존 Take 보존(Q5).

## 4. "고품질 승급" 문구 보강
**문제:** "고품질 승급"이 단일 동작처럼 보이나, 내부는 `final_regenerate / enhance / render_upscale` 중 하나.
**원칙:** 사용자는 내부 모드를 몰라도 됨. 버튼은 *결과 지향* 카피 + *비용 명시*.

| 위치 | 수정 전 | 수정 후(사용자 노출) |
|---|---|---|
| 비교화면 버튼 | `✨ 고품질 승급 12⚡` | **`✨ 게시용 품질로 다듬기 · 12⚡`** + 툴팁: "선택한 컷을 게시용 고품질로 다시 다듬어요. 크레딧이 사용돼요." |
| 03-ux-rules UX-2.2 | "이 컷 고품질로 승급" | "**게시용 품질로 다듬기**(1클릭). 내부 실행은 재생성/보정/업스케일 중 자동 선택 — 사용자는 결과만 본다. 버튼 옆 ⚡비용 항상 표기." |
| 05-quality "고품질 승급 추천" | 동일 라벨 | "게시용 품질로 다듬기" 추천으로 통일 |

**버튼 카피 후보(택1, 디렉터 취향):** ① `게시용 품질로 다듬기` (권장) ② `최종 품질로 마무리` ③ `게시 품질로 업그레이드`.
**내부 전제(Codex):** Q4 — `final_regenerate`(기본) / `enhance`(지원 모델) / `render_upscale`(렌더 옵션). 비용은 `estimate→reserve→capture`.

## 5. 실패 / 폴백 상태 UX (상황별 문구·버튼)
원칙: ① 모델명·기술용어 금지 ② **이전 작업·후보는 보존**됨을 안심시키기 ③ 1컷 문제가 전체를 막지 않음 ④ 다음 행동(버튼)을 명확히.

| # | 상황 | 사용자 메시지 | 버튼 | 동작/원칙 |
|---|---|---|---|---|
| F1 | provider 오류(엔진 실패) | "이 컷을 만드는 데 문제가 생겼어요. 잠깐 뒤 다시 시도해 볼게요." | `다시 시도` · `다른 방식으로 시도` | 자동 1회 재시도 → 실패 시 폴백 제안. 해당 컷 카드만 영향 |
| F2 | 쿼터 초과(요청 폭주) | "지금 생성 요청이 많아 잠시 줄 서 있어요. 자리가 나면 자동으로 이어서 만들어요." | `대기` · `완료되면 알림` | 큐 유지, 다른 컷은 계속 진행 |
| F3 | 특정 컷 생성 실패(부분 실패) | "이 컷만 다시 만들면 돼요. 나머지 컷은 그대로 잘 있어요." | `이 컷만 다시` | 실패 컷만 재큐. 전체 재생성 금지(P5) |
| F4 | 대체 방식으로 재시도(폴백 진행) | "이 컷은 다른 방식으로 다시 시도하고 있어요…" | (진행 표시·취소) | 라우터가 다음 후보로 자동 전환. 엔진명 비노출 |
| F5 | 크레딧 부족 | "크레딧이 부족해요. 지금까지 만든 건 그대로 저장돼 있어요." | `저비용으로 낮추기` · `크레딧 충전` | 작업 보존(UX-7.3). 저비용 티어 다운 동선 |
| F6 | 렌더 실패(최종 MP4) | "최종 영상으로 합치는 중 문제가 생겼어요. 고른 컷·자막·음악 설정은 그대로예요." | `다시 내보내기` | 이전 단계 산출물 보존, 재시도 무손실 |
| F7 | URL 만료 / 미디어 로딩 실패 | "영상을 불러오지 못했어요. 다시 불러올게요." | `새로고침` | 서명 URL 자동 갱신 후 재로드. 사용자에게 만료/서명 개념 비노출 |

공통 톤: 차분·간결·비난 없음("실패!" 대신 "다시 해볼게요"). 진행 중 상태엔 **항상 진행률·취소** 제공(UX-9.4).

## 6. BGM / TTS / 보이스 라이선스 UX
원칙: 라이선스 없는 음악·음성을 쓰는 것처럼 보이지 않게. 단, **법률 문구 벽이 아니라** 작은 helper로 자연스럽게.

| 위치 | 추가 문구(사용자 노출) | 형태 |
|---|---|---|
| BGM 선택 옆 | "🔒 라이선스 확인된 사운드만 제공해요." | 셀렉터 아래 small helper |
| 직접 업로드(음악/음성) | "직접 올린 음원·음성은 본인이 사용 권리를 가진 것만 올려 주세요." | 업로드 영역 helper + 1회 체크 |
| AI 보이스/TTS 선택 | "라이선스가 확인된 AI 보이스만 사용해요." | 보이스 드롭다운 옆 small |
| 내보내기 직전(상업 이용 시) | "상업적 사용이 가능한 사운드만 포함됐어요." (조건 충족 시) | 내보내기 요약에 작은 배지 |

**금지(제품·문구 모두):** 트렌드 음악 스크래핑, 출처 불명 BGM 번들, 라이선스 없는 음성 클론(Codex Q6와 일치).
**내부 전제(Codex):** `AudioProviderAdapter` + asset 단위 license metadata ledger.

## 7. QA 체크리스트 (Codex mock backend 연결 후)
mock provider + API 연결이 붙은 뒤, 프론트가 통과해야 하는 항목. 각 항목 = **합격 기준 / 확인 방법**.

| # | 체크 | 합격 기준 | 확인 방법 |
|---|---|---|---|
| Q-1 | 모델명 UI 누출 0건 | 전 화면 텍스트에 Runway/Veo/Luma/Gen-4 등 0 | 화면별 innerText 정규식 스캔(헤드리스) |
| Q-2 | 부분 실패 내성 | 10컷 중 2컷 실패해도 나머지 8컷 검토·진행 가능 | mock에서 2컷 failed 주입 → 비교화면 진행 확인 |
| Q-3 | 이전 Take 보존 | 재생성·승급·부분재시도 후 이전 후보 히스토리 잔존 | regenerate 호출 후 이전 takeId 조회 |
| Q-4 | 비용 표시 누락 0 | 생성·승급·내보내기 등 비용 발생 액션 100%에 ⚡ 인라인 | 비용 액션 버튼 라벨에 ⚡ 존재 검사 |
| Q-5 | 고급 옵션 접힘 유지 | 새 영상 1차 노출 컨트롤 ≤ 6, 고급은 펼쳐야 노출 | 초기 DOM에서 고급 패널 hidden 확인 |

| Q-7 | 크레딧 부족 작업 보존 | 잔액 부족 시 Project 상태 유지 + 충전/티어다운 동선 | mock 잔액 0 → 작업 데이터 잔존 확인 |
| Q-8 | 실패/폴백 문구 표시 | F1~F7 상황에서 §5 카피·버튼 정상 렌더 | mock 에러코드별 상태 주입 |
| Q-9 | "게시용 품질로 다듬기" 툴팁 | 버튼에 비용 + 툴팁 존재 | DOM title/aria 검사 |
| Q-10 | 라이선스 helper 노출 | BGM·업로드·AI보이스 영역에 §6 문구 존재 | 편집 화면 텍스트 검사 |
