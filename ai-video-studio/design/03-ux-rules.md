# 03 · 프론트엔드 UX 규칙 (UX Rules)

디렉터 요청 ③ 항목. 각 규칙은 **규칙 / 이유 / 수용 기준(테스트 가능)** 으로 적어 Codex·QA가 검증할 수 있게 한다.

## §1. 모델명 비노출 — "의도·티어"로만 말한다 (P1)

| ID | 규칙 | 이유 | 수용 기준 |
|---|---|---|---|
| UX-1.1 | 사용자 화면 어디에도 "Runway/Veo/Luma/Gen-4.5" 같은 **모델명·버전 미표기** | 비전문가에게 모델명은 노이즈. 시장 선두(Pika·Flow)가 표준 | 전 화면 텍스트 스캔 시 모델 고유명 0건(고급 옵션의 "엔진 선호"는 예외, 기본 숨김) |
| UX-1.2 | 엔진 뱃지는 **티어 의미**("고품질"·"빠른 미리보기")로 표기 | 사용자는 결과 등급만 알면 됨 | 뱃지 라벨이 티어 enum에서만 옴 |
| UX-1.3 | 라우팅 결정은 시스템이 (Intent+Tier+요구플래그)로 자동 | 모델 선택 부담 제거 | 사용자가 엔진을 고르지 않고도 전 플로우 완주 가능 |
| UX-1.4 | (고급) "엔진 선호"는 **옵트인 고급 옵션**으로만 | 파워유저 여지 + 기본 사용자 보호 | 고급 패널 펼치기 전엔 노출 안 됨 |

## §2. 3-way 품질 티어 — "고품질 / 빠른 생성 / 저비용" (디렉터 명시)

```
빠른 미리보기 🚀   ↔   저비용 💰   ↔   고품질 ✨
(반복·드래프트)       (대량·예산)        (게시·최종)
   기본값                명시 선택           승급 시
```

| ID | 규칙 | 이유 | 수용 기준 |
|---|---|---|---|
| UX-2.1 | **1차 생성은 항상 "빠른 미리보기"** 자동 | 싸고 빠르게 많이 보고 고르게(P2·P3) | 새 Shot 생성 시 기본 tier=`fast` |
| UX-2.2 | 만족 컷은 **"이 컷 고품질로 승급"** 1클릭 | Kling식 비용충격 회피, 쓴 만큼만 과금 | 승급 버튼이 선택된 Take에 항상 존재, 비용 표시 |
| UX-2.3 | "저비용"은 명시 선택(예산/대량 모드)에서만 | 품질 기대치 관리 | 기본 경로엔 미노출, 설정/대량 액션에서 등장 |
| UX-2.4 | 티어 변경은 **결과 품질을 말로 설명**("더 선명·자연스러운 모션") | 숫자·스펙 대신 체감 언어 | 툴팁이 해상도/모델 대신 체감 효과 서술 |

## §3. 복잡한 설정은 "고급 옵션"으로 숨긴다 (디렉터 명시)

| ID | 규칙 | 이유 | 수용 기준 |
|---|---|---|---|
| UX-3.1 | 기본 화면엔 **의도·티어·길이/비율(프리셋)** 만 | 결정 피로 최소화 | 새 영상 화면 1차 노출 컨트롤 ≤ 6개 |
| UX-3.2 | seed·negative prompt·fps·해상도·엔진선호·가이던스 등은 **접힌 고급 패널** | 파워유저용, 비전문가에겐 위험 | 고급 패널은 명시적으로 펼쳐야 보임 |
| UX-3.3 | 고급에서 바꾼 값은 **프리셋 위에 "사용자 지정" 배지** | 변경 사실 가시화 | 변경 시 배지 + "프리셋 복귀" 1클릭 |
| UX-3.4 | 프롬프트는 **SAEC 폼**(피사체/동작/환경/카메라/조명/스타일)로 구조화, 자유 텍스트는 보조 | 좋은 결과 유도, 빈칸 방지 | 폼 필드 = [템플릿 스키마](04-templates.md)와 1:1 |

## §4. 결과 비교·선택이 쉬워야 한다 (디렉터 명시)

| ID | 규칙 | 이유 | 수용 기준 |
|---|---|---|---|
| UX-4.1 | 컷당 후보(Take) **2~3개를 나란히**, 호버/포커스 시 자동재생 | 즉시 비교(Pika식 다량 생성→선택) | 비교 그리드 동시 표시 2~3, 재생 동시지원 |
| UX-4.2 | 선택은 **"이걸로" 단일 클릭**, 나머지는 후보로 보존 | 결정 마찰 0 | 클릭 1회로 `selectedTakeId` 확정 |
| UX-4.3 | 미선택 컷은 **품질 최고 Take 자동 추천** 선택 | 끝까지 멈추지 않게(완성 보장) | 검토 미완 컷도 추천값으로 렌더 가능 |
| UX-4.4 | 라벨은 **"A안/B안/C안"** (모델/시드 비노출) | 인지 부하↓ | 비교 라벨에 기술용어 0 |
| UX-4.5 | (선택) 유사 프롬프트 **커뮤니티 갤러리**로 영감·비교 | Sora 피드식 무료 비교엔진 | v2 후보(필수 아님) |

## §5. 실패/불만 컷만 재생성 (디렉터 명시 · P5)

|---|---|---|---|
| UX-5.1 | 재생성 범위는 **Shot 단위 기본**, 전체 재생성 금지 | 비용·일관성 보호 | "다시" 버튼은 해당 Shot만 큐잉 |
| UX-5.2 | **서브클립(2~16초) 부분 재생성** 지원("이 부분만 다시") | LTX Retake식 정밀 수정 | 구간 선택 후 그 구간만 재생성 |

## §10. 라우팅 결정 로직 (프론트 → 백엔드 "요구"만)
프론트는 **엔진을 고르지 않는다.** 대신 각 Shot에 아래 **요구 플래그**를 실어 보내고, 백엔드 라우팅 테이블이 엔진을 정한다(→ [계약 §4](06-frontend-backend-contract.md#4-티어엔진-라우팅-요구사항)).

| 요구 플래그(프론트가 세팅) | 의미 | 라우팅에 주는 힌트 |
|---|---|---|
| `tier` | fast / final / economy | 1차=fast, 승급=final |
| `needsLipsyncAudio` | 대사 립싱크/네이티브 사운드 필요 | → Veo 3.1 우선 |
| `imageToVideo` | 참고 이미지 기반 | → Luma Ray 2 우선 |
| `motionHeavy` | 물/천/머릿결 등 물리모션 | → Luma Ray 2 |
| `characterLock` | 인물 일관 필요 | → Gen-4.5/Veo reference |
| `aspect`,`durationSec`,`resolution` | 포맷 요구 | 가용 엔진 필터 |
| `region` | 사용자 지역(얼굴 제한 등) | 제한 엔진 제외 |

> **불변식:** 프론트는 위 "요구"만 안다. 어떤 엔진이 선택됐는지는 디버그/관측용으로 응답에 `engineUsed`가 와도 **사용자 화면엔 표시하지 않는다**(UX-1.1).
