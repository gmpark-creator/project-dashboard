# 04 · 프롬프트 / 스토리보드 템플릿 (Templates)

디렉터 요청 ④ 항목. 6개 목적별로 **기본값 → 스토리보드 구조 → SAEC 프롬프트 스켈레톤**. 모든 템플릿은 공통 스키마(§맨아래)를 따르며, Codex는 이를 **데이터(JSON)로** 적재해 코드 수정 없이 추가/수정한다.

## 공통 원칙 (리서치 기반)
- **SAEC 프레임워크**: 모든 샷 프롬프트는 `Subject·Action·Environment·Cinematics(camera/framing/lighting/style)` 골격. 정적 묘사 금지 — **동작·카메라 모션은 동사로 명시**.
- **분해 규칙**: 1 장소/시간 변화 = 1 Scene. 1 주요 동작 = 1 Shot. 한 컷에 두 동작/두 장소 금지.
- **9:16 마스터 우선**: 소셜이면 9:16로 만든 뒤 16:9·1:1 파생.
- **3컷 산출**: 한 개념에서 6s(훅)·15s(표준)·30s(풀) 세 길이를 항상 뽑아 채널 커버리지 극대화.
- **프롬프트 ≤150단어**, 네거티브 모션 프롬프트(`흔들림·플리커·모핑·프레임 불일치`) 포함.

> **R2 보정(Codex):** 아래 표의 「엔진 적합(백엔드)」에 적힌 모델명은 *예시 후보*다. 실제 엔진은 라우터가 **입력 타입·길이·비율·해상도·지역 필터** 후 선택한다(`codex/config/routing.config.json`). 특히 ▸**Gen-4 Turbo는 image-to-video 입력 후보**(text-only 빠른 기본값 아님) ▸**4K는 provider 지원 또는 렌더 업스케일 옵션**(기본 계약 720p/1080p). 사용자에겐 엔진명 대신 「빠른 미리보기 / 게시용 품질」 티어로만 노출.

## 템플릿 1 · 쇼츠 (Short-form / Reels·Shorts·TikTok)
| 속성 | 기본값 |
|---|---|
| 비율 / 길이 | **9:16** / 15s (옵션 6·30s) |
| 샷수 / 페이싱 | 4~10컷, 컷당 1~2s, **훅 1~2초 내 등장 필수** |
| 톤 | 네이티브·통통 튀는, 과한 프로덕션보다 생생함 |
| 티어 힌트 | 빠른 미리보기로 다량 → 베스트만 고품질 승급 |
| 엔진 적합(백엔드) | 빠른 동적 페이싱 → Gen-4 Turbo / Ray 2 Flash, 사운드 필요 시 Veo 3.1 |
| 자막/오디오 | 자막 번인 기본, 트렌디 BGM, (선택) 보이스 |

**스토리보드 구조**: `훅(0~2s)` → `전개 3~6컷` → `반전/하이라이트` → `CTA/루프`.
**SAEC 스켈레톤(예)**: *S* 딸기라떼 잔 · *A* 김이 모락 피며 빨대가 꽂힌다 · *E* 밝은 카페 창가, 아침 햇살 · *C* ECU·살짝 푸시인·소프트 윈도우라이트·산뜻 팝 톤.

## 템플릿 스키마 (Codex 적재용 — JSON)
프론트는 이 스키마를 읽어 화면2의 목적 카드·화면3의 기본 분해·SAEC 폼을 채운다. **데이터로 분리** → 새 목적 추가 시 코드 무변경.

```jsonc
// templates/<intent>.json
{
  "intent": "shorts",                       // shorts|product_ad|app_intro|real_estate|education|brand
  "label": "쇼츠",
  "defaults": {
    "aspect": "9:16",
    "durationSec": 15,
    "durationCuts": [6, 15, 30],            // 항상 뽑는 3길이
    "shotCount": { "min": 4, "max": 10 },
    "shotDurationSec": { "min": 1, "max": 2 },
    "tier": "fast",                          // 1차 생성 티어
    "captions": "burn-in",
    "bgm": "auto",
    "voiceover": "optional"
  },
  "requirementHints": {                      // 라우팅 요구플래그 기본
    "needsLipsyncAudio": false,
    "motionHeavy": false,
    "characterLock": false
  },
  "storyboardSkeleton": [                    // 자동 분해 시드
    { "role": "hook",   "durationSec": 2, "note": "0~2초 내 훅" },
    { "role": "develop","count": [3,6] },
    { "role": "highlight" },
    { "role": "cta" }
  ],
  "saecFieldDefaults": {                     // SAEC 폼 placeholder/기본
    "subject": "", "action": "", "environment": "",
    "camera": "", "framing": "", "lighting": "",
    "style": "네이티브·산뜻 팝",
    "negative": "흔들림, 플리커, 모핑, 프레임 불일치"
  },
  "promptRules": { "maxWords": 150, "onePrimaryMotionPerShot": true }
}
```

### SAEC 샷 프롬프트 → 엔진 전달 형태 (프론트 산출, 백엔드 어댑터가 엔진별 변환)
```jsonc
{
  "shotId": "2.1",
  "saec": {
    "subject": "딸기라떼 한 잔",
    "action": "김이 모락 피어오르며 빨대가 꽂힌다",
    "environment": "밝은 카페 창가, 아침 햇살",
    "camera": "살짝 푸시인(dolly-in)",
    "framing": "익스트림 클로즈업",
    "lighting": "소프트 윈도우 라이트, 45도 키",
    "style": "산뜻한 팝, 광고 톤",
    "negative": "흔들림, 플리커, 모핑"
  },
  "durationSec": 3,
  "aspect": "9:16",
  "requirements": { "tier": "fast", "imageToVideo": false, "characterLock": false }
}
```

> **분해 엔진(LLM) 요구사항**: 아이디어/대본 → 위 구조의 Scene[]·Shot[] 배열 생성. (LLM 제공자/구현은 Codex 영역. 프론트는 "구조화된 스토리보드를 돌려주는 분해 API"를 기대한다 → [계약 §3](06-frontend-backend-contract.md#3-주요-api-표면-프론트가-기대하는-요구사항).)
