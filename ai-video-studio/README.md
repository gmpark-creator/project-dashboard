## 0. 제품 한 줄 논지 (Product Thesis)

> **"모델 이름을 몰라도, 아이디어 한 줄이면 완성된 MP4가 나온다."**
> Runway·Luma·Veo를 **베끼지 않고 엔진으로 깔고**, 그 위에 *비전문가가 영상 한 편을 끝까지 완성*하게 해 주는 **오케스트레이션 레이어**를 올린다.

경쟁 도구(Runway/Pika/Kling/Flow…)는 "클립 생성기"에 가깝다. 사용자는 모델·파라미터·크레딧을 직접 다뤄야 하고, 여러 컷을 모아 한 편을 만드는 일은 외부 편집기로 떠넘긴다. **Cutpilot의 차별점은 "한 편 완성"을 책임지는 것** — 분해·생성·비교·선택·편집·내보내기를 하나의 흐름으로 잇고, 그 안에서 *어떤 엔진을 쓸지는 시스템이 결정*한다.

### 설계를 관통하는 6대 원칙 (경쟁사 리서치에서 검증된 패턴)
| # | 원칙 | 근거(시장 검증) |
|---|------|----------------|
| P1 | **모델명을 숨기고 "의도·티어"로 말한다** | Pika(기능 동사)·Google Flow(자동 라우팅)가 표준 |
| P2 | **기본은 드래프트, 만족하면 1클릭 고품질 승급** | Kling Standard→Pro의 개선판(비용 급증 충격 제거) |
| P3 | **첫 결과는 "완성본"부터** (빈 캔버스 금지) | InVideo: AI가 500+ 결정을 대신해 초안 완성 |
| P4 | **편집은 대화로** (타임라인은 고급 옵션으로 숨김) | InVideo Magic Box · Captions 챗 편집 |
| P5 | **실패/불만 컷만 콕 집어 재생성** (서브클립 단위) | LTX Retake(2~16초 구간만 재생성) |
| P6 | **비용은 선택하는 그 버튼 위에 표시** | Higgsfield의 함정(모델 잘못 골라 크레딧 소진) 회피 |

## 1. 엔진 전략 — "고품질 / 빠른 생성 / 저비용" 추상화

사용자에게 노출되는 건 **모델이 아니라 3개의 다이얼**과 **의도(목적)** 뿐. 실제 엔진 선택은 **백엔드 라우팅 테이블**(→ [계약 문서 §4](design/06-frontend-backend-contract.md#4-티어엔진-라우팅-요구사항))이 담당한다. 프론트는 *어떤 엔진인지 모른 채* "의도 + 티어 + 샷 요구플래그"만 보낸다.

### 사용자가 보는 3-way 티어 (프론트)
| 티어(사용자 표기) | 의미 | 언제 자동 적용 |
|---|---|---|
| 🚀 **빠른 미리보기** | 싸고 빠른 드래프트, 반복용 | 모든 컷의 **1차 생성 기본값** (P2·P3) |
| ✨ **고품질** | 게시용 최종 품질 | 사용자가 컷을 "확정"하거나 "고품질 승급" 누를 때 |
| 💰 **저비용** | 적당한 품질·최저가 | 대량 생성/예산 모드, 사용자가 명시 선택 시 |

### 백엔드가 매핑하는 엔진 (2026-06 기준 — 변동성 높음, Codex가 출시 시 재검증)
| 사용자 의도/요구 | 1차 추천 엔진 | 대안 | 이유 |
|---|---|---|---|
| 빠른 드래프트(무음) | **Gen-4 Turbo** / **Ray 2 Flash** | Veo 3.1 Lite | 초당 비용 최저, 반복에 적합 |
| 고품질 최종(시네마틱·캐릭터 일관) | **Runway Gen-4.5** | Veo 3.1 | 리더보드 1위, 멀티샷 일관성 |
| **대사/립싱크·네이티브 사운드 필요** | **Veo 3.1** | Gen-4.5 | 유일하게 대사 립싱크+SFX 단일 생성 |
| **이미지→영상 / 제품 / 자연 물리모션**(물·천·머릿결) | **Luma Ray 2** | Gen-4.5 | 모션 코히런스 최상, API 생태계 넓음 |
| 세로 소셜 + 사운드 | **Veo 3.1**(9:16 네이티브 오디오) | Gen-4.5 | 립싱크 세로 컷 |
| 4K 필요 | **Veo 3.1** | Gen-4.5(업스케일) | Veo만 네이티브 4K |

> ⚠️ **엔진 스펙은 빠르게 바뀐다.** Gen-4.5(2025-12-01 출시)·Veo 3.1(2025-10)·Ray 2(2025, 현재 Ray 3가 상위)·각 모델 오디오 지원·API 가용성은 [엔진 리서치 부록](design/07-engine-research-appendix.md)에 출처와 함께 기록. **라우팅 테이블은 "데이터"로 분리**해 Codex가 코드 수정 없이 갱신할 수 있어야 한다(→ 계약 §4).

## 3. 용어 (Glossary) — 프론트/백 공통 어휘
| 용어 | 정의 |
|---|---|
| **Project** | 한 편의 영상 작업 단위. 1 idea → N Scenes. |
| **Scene** | 장소/시간/톤이 바뀌는 경계. Project당 보통 3~8개. |
| **Shot** | Scene 안의 한 컷(1~5초). 생성·재생성·선택의 최소 단위. |
| **Take(변형)** | 한 Shot에 대해 생성된 여러 후보 결과(비교·선택 대상). |
| **Generation Job** | 한 Take를 만드는 비동기 작업(엔진 호출). 상태: queued→running→done/failed. |
| **Render Job** | 선택된 Take들 + 자막/음성/BGM을 합쳐 최종 MP4를 굽는 작업. |
| **Intent** | 영상 목적(쇼츠/광고/앱소개/공간/교육/캠페인). 템플릿·기본값을 결정. |
| **Tier** | 빠른 미리보기 / 고품질 / 저비용 (사용자가 보는 품질 다이얼). |
| **Routing** | (Intent + Tier + 샷 요구플래그) → 엔진 결정. **백엔드 책임**, 데이터 테이블로 분리. |
