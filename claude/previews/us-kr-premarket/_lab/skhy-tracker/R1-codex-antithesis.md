**Q3 분모** — 7.46억은 오류. 정답은 후보 3개 중 하나가 아니라 **날짜별 KRX 상장주식수**. Gap을 정확한 보유주수로 계산하면 분모는 Gap에 영향 없음. **반대로 반올림 지분율로 보유량을 역산하는 것은 금지**(52.60% 적용 시 분모 선택만으로 최대 −15,149,244주 편차, 반올림 자체로도 ±36,525주 = ADS ±365,250주).

**Q4 프리미엄** — **실재한다.** ADS 방향 `×10` 맞음. 본주 raw close = adjusted close, split 없음. 분배금·원천세·Citi 수수료·carry는 20~60% 괴리를 설명할 규모가 아님. ⚠️ **스펙 validator의 `premium ≤ +60%`가 실제값 60.34%(일봉 FX 기준 62.56%)를 오염으로 오판**한다.

**Q5 프리미엄 원인 6가지** — ①비동시 가격 비교 ②신규 예탁의 법적·운영적 제한(Deposit Agreement·발행사 사전동의·Citi issuance/cancellation) ③시장 분절과 미국 투자자의 한국 직접투자 제약 ④공매도·대차 부족(borrow fee/utilization·Reg SHO FTD) ⑤SMH 편입 기대 선반영 ⑥실제 ADS outstanding 오인(177.9M은 최초 발행량이지 현재 outstanding 보장 아님)

**Q6 Gap 방법론** — **방향성 전제는 일부 지지되나 현재 식은 DR 전환을 식별하지 못한다.**
실제 항등식: `Δ외국인보유 = 전 시장 결제완료 순매매 + 장외·계좌간 이전 + 신주·소각·배정 + 등록분류 변경 + DR 발행·소각 + 정정`
→ `Δ보유 − 장내 순매수`는 **DR 전환량이 아니라 미설명 잔차**. Citi 월별 outstanding과 반복적으로 맞아야만 DR 추정치로 승격 가능. 그 전엔 UI 문구도 **"미설명 외국인 보유 변동"**이어야 한다.
⚠️ lag를 "잔차 표준편차 최소"로 고르면 **실제 DR 이벤트까지 흡수하는 과적합** 가능.

**Q7 수급 미스매치** — 높은 회전율은 "극단적·흡수 불가능" 주장을 **약화**하나 가격 충격이 없다는 뜻도 아니다. $154.41 기준 $20억=12.95M ADS·$40억=25.90M ADS = 초기 ADS의 7.28~14.56%, **최근 평균 거래량의 0.29~0.58일분**. 게다가 **편입은 미확정**(MarketVector 8/31 데이터·9/11 발표). $20~40억은 시나리오이지 확정 필요매수액이 아니다.

**Q8 시그널 점수화** — **현재 형태로는 표현 규율과 정면 충돌, 게시 불가.** 결함 12종(측정오차보다 작은 +1주도 B점수 / `THRESHOLD` 미정의 / 동적 threshold가 스스로 움직임 / 슬라이더로 결론 조정 가능해 재현성 없음 / 5일 window 근거·out-of-sample 없음 / 가중치 calibration 없음 / premium level과 change 중복 / 고정 friction band / 분모 변경으로 지분율이 움직임 / 월2회 short interest를 5일 신호에 혼입 / missing data 중단 규칙 없음 / 점수→신뢰도 통계적 매핑 없음).

## 스펙 자체의 추가 결함 (Codex 지적)

- `INITIAL_ADR_SHARES=17,790,000`은 잘못된 이름 → `INITIAL_UNDERLYING_COMMON`
- F-6 등록용량 / 실제 ADS outstanding / 신규 발행 가능량 미분리
- "날짜 연속성 결측 없음"이 양 시장 휴장일 차이 및 "forward-fill 금지"와 충돌 → 시장별 expected calendar 별도 검증 필요
- `premium −20~+60%`, 일간 지분율 `<5%p`는 integrity 검사가 아니라 **임의의 경제적 범위** → 실제값을 오염으로 오판
- "마지막 정상 데이터 계속 표시" 설계에 **TTL·stale overlay 없음** → 빨간 상태바만으로 과거 데이터가 현재처럼 보임
- Citi 수동값을 "유일한 정답지"라 했으나 발표주기·정의·소급정정·issued vs outstanding 차이 미검증
- GitHub Actions가 raw 응답과 SQLite를 커밋하는 구조는 **데이터 라이선스·저장소 용량 양쪽에 위험**
- SEC 6-K/F-6 경보를 "발행 창구 개방"과 동일시 → 등록은 필요조건일 수 있으나 실제 예탁 동의·운영 상태를 증명 못 함
- manual JSON에 입력자·근거 URL·as-of·단위·검토상태 없음
- short-interest가 선택 데이터인데 점수엔 가중치가 있어 missing-data 계약 모순
